# Data Repository Split — Plan

Branch: `feat/data-repo`
Start date: 2026-08-04

---

## Situation

The harness repo (`kernel-test`) currently stores two distinct categories of data
in the same git repository:

- **Tooling** — scripts, Makefile, test scripts, config fragments, CLAUDE.md
- **Data** — 691 archived `.config` files (83 MB), FINDINGS.md kernel bug notes,
  generated index files (`configs/archive_*/index.*`)

The `configs/archive_*/` directories grow with every test run and have already
ballooned `git clone` and `git log` times.  `reports/` (already gitignored) and
`consolidation/` (gitignored) also have no natural home.

Keeping test data in the harness repo creates friction: every `git pull` on a new
machine fetches hundreds of MB of kernel configs that the clone does not need to
build or test.

---

## Goals

1. Move all test data out of the harness repo into a dedicated sibling repo
   (`kernel-test-data/`)
2. Harness scripts write directly into `kernel-test-data/` and auto-commit after
   each write
3. Single `DATA_REPO` variable wires the two repos together; error if unset
4. `make bootstrap` handles cloning or updating `kernel-test-data/` automatically
5. FINDINGS.md split: kernel bug notes → data repo; tooling notes → harness repo
6. Clean migration: existing committed data moves out of the harness in this PR

---

## New variable: DATA_REPO

```makefile
DATA_REPO ?= $(HOME)/git/kernel-test-data   # Makefile default (mainline clone)
```

Set identically in every preset file so all four clone types point to the same
data repo by default and the value is visible per-clone:

| Preset | Sets |
|--------|------|
| `presets/kernel-test-stable.mk` | `DATA_REPO ?= $(HOME)/git/kernel-test-data` |
| `presets/kernel-test-stable-rc.mk` | `DATA_REPO ?= $(HOME)/git/kernel-test-data` |
| `presets/kernel-test-next.mk` | `DATA_REPO ?= $(HOME)/git/kernel-test-data` |
| _(mainline — no preset)_ | falls back to Makefile default |

Override per-machine via `local.mk` (gitignored) if a different path is needed
(e.g. a different disk on Hetzner).  Tilde-expanded and absolutified at parse
time (same pattern as `KERNEL_TREE`).

If `DATA_REPO` is unset or the directory does not exist, scripts that need it
print an error and exit 1.  No silent fallback to the harness directory.

## kernel-test-data/ directory structure

```
kernel-test-data/
  reports/                    test run report dirs (label-version-datetime-tag/)
  configs/
    archive_passed/           .config files that produced a PASS result
    archive_failed/           .config files that produced a FAIL result
  consolidation/              gitignored — local cross-source merge workspace
    <source>/
      archive_failed/
        index.txt             manually copied from each clone/machine
    index.txt                 generated by make consolidate-index
    index.html
  FINDINGS.md                 kernel bug investigation notes (moved from harness)
  .gitignore                  excludes consolidation/
```

`reports/` is committed (was gitignored in the harness; now a first-class citizen
in the data repo so results are shared across machines via git push/pull).

## bootstrap.sh behaviour

`make bootstrap` / `lib/bootstrap.sh` gains a data-repo step:

```sh
DATA_REPO="${DATA_REPO:-$HOME/git/kernel-test-data}"
if [[ ! -d "$DATA_REPO" ]]; then
    git clone https://github.com/bb-claw/kernel-test-data.git "$DATA_REPO"
else
    git -C "$DATA_REPO" pull --rebase
fi
```

Run once on initial setup; subsequent `make bootstrap` calls stay idempotent
(pull only).

## Per-run write flow

Each script that writes to the data repo follows the same three-step pattern after
its write:

```sh
git -C "$DATA_REPO" pull --rebase
git -C "$DATA_REPO" add <paths>
git -C "$DATA_REPO" commit -m "chore(<scope>): <description>"
```

User pushes manually when ready: `git -C ~/git/kernel-test-data push`.

### lib/report.sh

Writes `$DATA_REPO/reports/<label>-<version>-<datetime>/`.  Auto-commits:
```
chore(report): add mainline v7.2-rc5 2026-08-04_12-00-00 results
```

### scripts/config-archive.sh

Reads `$DATA_REPO/reports/` (same as before but rooted at DATA_REPO).  Writes
`.config` files and indexes into `$DATA_REPO/configs/archive_*/`.  Auto-commits:
```
chore(config-archive): update mainline v7.2-rc5 archives
```

### scripts/consolidate-index.sh

Reads `$DATA_REPO/consolidation/*/archive_failed/index.txt`.  Writes
`$DATA_REPO/consolidation/index.{txt,html}`.  These files are gitignored in the
data repo — no commit step needed.

## FINDINGS.md split

The current `FINDINGS.md` contains two kinds of entries:

- **Kernel bugs** — failure SHAs, dmesg excerpts, upstream patch links; these
  belong with the data (the referenced report dirs now live in the data repo)
- **Tooling notes** — harness bugs, script fixes, build infrastructure issues;
  these belong with the code

Split:
- Move kernel bug entries → `$DATA_REPO/FINDINGS.md`
- Keep tooling notes → `kernel-test/FINDINGS.md`

## Migration steps (one-time, done in this PR)

```sh
# 1. Create and initialise the data repo locally
git init ~/git/kernel-test-data
cd ~/git/kernel-test-data
mkdir -p reports configs/archive_passed configs/archive_failed consolidation
printf 'consolidation/\n' > .gitignore
git add .gitignore
git commit -m "chore: initial data repo structure"

# 2. Copy existing harness data into the data repo
cp -r ~/git/kernel-test/configs/archive_passed/. ~/git/kernel-test-data/configs/archive_passed/
cp -r ~/git/kernel-test/configs/archive_failed/. ~/git/kernel-test-data/configs/archive_failed/
git -C ~/git/kernel-test-data add configs/
git -C ~/git/kernel-test-data commit -m "chore(migrate): import configs/archive_* from harness repo"

# 3. Split FINDINGS.md (kernel bugs → data repo; tooling → harness)
# (manual edit step — see FINDINGS.md split section above)
git -C ~/git/kernel-test-data add FINDINGS.md
git -C ~/git/kernel-test-data commit -m "chore(migrate): import kernel bug findings"

# 4. Remove data from harness repo
cd ~/git/kernel-test
git rm -r configs/archive_passed/ configs/archive_failed/
# Edit FINDINGS.md to remove migrated kernel bug entries
git add .gitignore FINDINGS.md
git commit -m "chore(data-repo): remove archived configs and kernel findings"

# 5. Push data repo to GitHub
git -C ~/git/kernel-test-data remote add origin git@github.com:bb-claw/kernel-test-data.git
git -C ~/git/kernel-test-data push -u origin main
```

## Multi-machine sync

Both local and Hetzner clones write to the same remote:

```sh
# After any make report / make config-archive run, the data repo has a new
# commit. Push it:
git -C ~/git/kernel-test-data push

# On the other machine, before the next run:
git -C ~/git/kernel-test-data pull --rebase
# (make bootstrap does this automatically when run)
```

The pull --rebase inside each write step prevents conflicts when two machines
write in close succession.  Runs on the same machine are always sequential.
Hetzner and local rarely run at exactly the same time; if they do, the second
push will require a pull --rebase before it succeeds.

## How to verify this branch

1. **Unit: DATA_REPO unset** — unset DATA_REPO; run `make config-archive`; expect
   error message and exit 1, no writes
2. **Unit: bootstrap clone** — remove `~/git/kernel-test-data`; run
   `make bootstrap`; expect clone to succeed and directory to appear
3. **Unit: bootstrap pull** — with data repo present; run `make bootstrap`; expect
   `git pull --rebase` only (no re-clone)
4. **Integration: make report** — run `make all NO_FETCH=1 CONFIGS=tinyconfig
   ARCHS=x86_64`; check that a new dir appears in `$DATA_REPO/reports/` and a
   new commit appears in the data repo (`git -C ~/git/kernel-test-data log -1`)
5. **Integration: make config-archive** — run `make config-archive`; check that
   `$DATA_REPO/configs/archive_*/` is updated and committed
6. **Integration: make consolidate-index** — populate
   `$DATA_REPO/consolidation/local-mainline/archive_failed/index.txt`; run
   `make consolidate-index`; check output at `$DATA_REPO/consolidation/index.html`
7. **Make replay** — pass `CONFIG_FILE=$DATA_REPO/configs/archive_failed/<sha>.config`;
   confirm the pipeline runs unchanged
8. **git clone clean** — `git clone` the harness repo into a temp dir; confirm
   no `.config` files are in `configs/archive_*/` and no reports in `reports/`

## Non-goals

- Automated push to remote (user pushes manually; avoids credentials in scripts)
- Merging `archive_passed/` into a unified index (passed configs are for replay only)
- Submodule linking between harness and data repo (too much friction on clone)
- Storing build logs or dmesg in the data repo (too large; already gitignored)
